# Участие в разработке

Спасибо за интерес к проекту Aerial Sentinel! Мы рады приветствовать участников.

## Как начать

### Форк и клонирование

```bash
# Форк репозитория на GitHub
# Клонирование вашего форка
git clone https://github.com/ВАШ_USERNAME/OsintPlatform_project.git
cd OsintPlatform_project

# Добавление upstream удалённого репозитория
git remote add upstream https://github.com/LernerF/OsintPlatform_project.git
```

### Настройка окружения для разработки

**Бэкенд:**
```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**Фронтенд:**
```bash
cd frontend
npm install
```

## Рабочий процесс

### 1. Создайте ветку функции

```bash
git checkout -b feature/описание-функции
```

Используйте описательные имена веток:
- `feature/` для новых функций
- `fix/` для исправления ошибок
- `docs/` для документации
- `refactor/` для рефакторинга

### 2. Внесите изменения

- Пишите чистый, читаемый код
- Следуйте стилю проекта
- Добавляйте комментарии к сложным частям

### 3. Тестирование

```bash
# Запуск тестов бэкенда
cd backend
pytest

# Проверка стиля кода
ruff check .
ruff format .
```

### 4. Коммиты

Пишите понятные сообщения коммитов:

```bash
git commit -m "Краткое описание изменения"
```

Примеры хороших сообщений:
- "Add geolocation validation for events"
- "Fix WebSocket reconnection issue"
- "Update deployment documentation"

### 5. Push и Pull Request

```bash
# Обновите вашу ветку с upstream
git fetch upstream
git rebase upstream/main

# Push на ваш форк
git push origin feature/описание-функции
```

На GitHub создайте Pull Request с описанием:
- **Что изменилось**: Краткое описание
- **Почему**: Обоснование изменения
- **Как тестировать**: Инструкции для проверки
- **Checklist**:
  - [ ] Код следует стилю проекта
  - [ ] Добавлены необходимые тесты
  - [ ] Обновлена документация
  - [ ] Нет конфликтов с main

## Стандарты кода

### Python (бэкенд)

- Используйте PEP 8 стиль
- Type hints обязательны для функций
- Максимальная длина строки: 100 символов
- Используйте `ruff` для линтинга

```python
from typing import Optional

def process_message(text: str, source_id: int) -> Optional[dict]:
    """Process a Telegram message.
    
    Args:
        text: Message content
        source_id: ID of the message source
        
    Returns:
        Processed event dict or None if not relevant
    """
    pass
```

### TypeScript (фронтенд)

- Используйте типы везде
- Функции должны иметь return type
- Используйте const по умолчанию

```typescript
interface Event {
  id: number;
  title: string;
  confidence: number;
}

function processEvent(event: Event): Promise<void> {
  // implementation
}
```

### Документация

- Комментарии на русском или английском (последовательно)
- Docstrings для модулей, классов и функций
- README для каждого значимого модуля

## Типы вкладов

### Отчёты об ошибках

Перед созданием issue проверьте:
- Ошибка ещё не зарепортирована
- Используется последняя версия кода
- Есть достаточно информации для воспроизведения

**Информация для включения:**
- Шаги воспроизведения
- Ожидаемое поведение
- Фактическое поведение
- Версия ПО, ОС, браузер
- Логи ошибок (если есть)

### Запросы функций

Опишите:
- Что вы хотите добавить
- Почему это полезно
- Возможные варианты реализации

### Улучшение документации

- Исправление опечаток
- Уточнение инструкций
- Новые примеры использования
- Переводы на другие языки

## Процесс ревью

1. Один или несколько мейнтейнеров ревьюят ваш PR
2. Могут быть запросы на изменения
3. Обновите PR согласно feedback
4. После одобрения PR будет смерджен

## Кодекс поведения

### Наши принципы

- Будьте уважительны к другим участникам
- Сосредоточьтесь на коде, а не на личности
- Приветствуйте разные мнения
- Помогайте новичкам
- Поддерживайте этику использования

### Неприемлемое поведение

- Дискриминация любого рода
- Харассмент или угрозы
- Спам или рекламирование
- Попытки использовать ПО для вреда

Нарушители могут быть удалены из проекта.
