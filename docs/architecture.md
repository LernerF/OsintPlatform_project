# Архитектура системы

## Обзор

Aerial Sentinel следует микросервисной архитектуре с чётким разделением между слоями сбора данных, обработки и представления.

## Схема базы данных

### Основные таблицы

```sql
-- Источники (Telegram-каналы/чаты)
CREATE TABLE sources (
    id INTEGER PRIMARY KEY,
    telegram_id TEXT UNIQUE NOT NULL,
    title TEXT NOT NULL,
    type TEXT NOT NULL,  -- 'channel', 'chat', 'user'
    city TEXT,
    region TEXT,
    enabled BOOLEAN DEFAULT true,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- Сообщения (сырые Telegram-сообщения)
CREATE TABLE messages (
    id INTEGER PRIMARY KEY,
    source_id INTEGER REFERENCES sources(id),
    telegram_message_id TEXT,
    text TEXT,
    processed_at TIMESTAMP,
    status TEXT,  -- 'pending', 'filtered', 'classified', 'event'
    created_at TIMESTAMP
);

-- События (обнаруженные инциденты)
CREATE TABLE events (
    id INTEGER PRIMARY KEY,
    message_id INTEGER REFERENCES messages(id),
    source_id INTEGER REFERENCES sources(id),
    cluster_id INTEGER REFERENCES clusters(id),
    event_type TEXT,
    confidence REAL,
    risk_level TEXT,
    summary TEXT,
    location_text TEXT,
    city TEXT,
    district TEXT,
    lat REAL,
    lon REAL,
    precision TEXT,  -- 'city', 'district', 'street', 'address', 'landmark'
    created_at TIMESTAMP
);

-- Кластеры (сгруппированные события)
CREATE TABLE clusters (
    id INTEGER PRIMARY KEY,
    first_event_id INTEGER REFERENCES events(id),
    last_seen_at TIMESTAMP,
    event_count INTEGER,
    centroid_lat REAL,
    centroid_lon REAL
);

-- Кэш геокодирования
CREATE TABLE geocoding_cache (
    id INTEGER PRIMARY KEY,
    query TEXT UNIQUE NOT NULL,
    formatted_address TEXT,
    lat REAL,
    lon REAL,
    precision TEXT,
    provider TEXT,
    created_at TIMESTAMP
);
```

## Конкурентность и ограничения запросов

### Telegram-коллектор

- **Режим realtime**: Событийный приём сообщений
- **Режим polling**: Настраиваемый интервал (по умолчанию: 300 сек)
- **Комментарии**: Адаптивный polling на основе возраста ветки
  - 0-5 мин: каждые 15 сек
  - 5-60 мин: каждую минуту
  - 1-6 часов: каждые 5 мин
  - 6-24 часов: каждые 15 мин
  - 24+ часов: остановить polling

### OpenRouter API

- Макс. одновременных запросов: 8
- Таймаут: 30 секунд
- Повтор при ошибке: 3 попытки с экспоненциальной задержкой

### Геокодирование

- **Nominatim**: 1 запрос в секунду (строгое ограничение)
- **Яндекс**: 3 конкурентных запроса
- Размер кэша: 2000 записей с LRU-исключением

### Доставка webhook

- Макс. конкурентных: 5
- Повторы: 3 попытки (задержки 1с, 3с, 10с)
- Ключ идемпотентности: `event-{id}`

## Вопросы безопасности

1. **API-ключи**: Хранятся в переменных окружения, никогда в коде
2. **Telegram-сессии**: Хранятся в отдельном volume, не в Git
3. **База данных**: SQLite-файл вне репозитория
4. **Сеть**: Бэкенд доступен только через обратный прокси
5. **Аутентификация**: Basic auth на публичном шлюзе
